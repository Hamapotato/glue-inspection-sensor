# 涂胶检测传感器方案汇报摘要

> 本文用于向老师汇报项目总体方案和阶段安排，详细技术依据见
> [产品开发路线图](product-development-roadmap.md)。

## 1. 可直接口述的总体方案

老师，我的方案不是一开始就自研整块 RK3588 板和三路相机，而是按照
“论文复现—能力样机—工程样机—产品化”的路线逐步推进。

最终产品是一体化三相机涂胶检测传感器。传感器内部集成三路全局快门相机、
镜头、红光频闪照明、硬件触发电路和 RK3588 计算板。三路相机通过短 MIPI
链路接入 RK3588，在边缘端完成图像处理、胶条尺寸测量、缺陷检测和 RKNN
模型推理，输出断胶、过宽、过窄、位置偏差、多胶、气泡等结果，同时携带
置信度、相机编号、配方版本、模型版本和时间戳。

传感器通过千兆以太网连接工控机。工控机只负责示教、配方管理、实时显示、
缺陷回放和报表，不承担实时推理；再由工控机或工业网关连接机器人和 PLC。
触发和照明同步由独立 MCU 负责，保证三路相机同步曝光，并避免让 Linux
直接承担硬实时控制。

整个研发过程设置阶段评审：先证明“能稳定成像”，再证明“能准确检测”，
然后验证 RK3588 边缘链路和自研载板，最后进入可靠性和现场试点。第一版
不直接自研核心板和裸 CMOS，也会控制功能范围，优先完成三路成像、胶条
可测、缺陷可判、结果可追溯。

## 2. 总体架构

```text
三路相机 + 镜头 + 频闪照明
          |
          | 短 FPC / MIPI CSI-2
          v
RK3588 SoM + 自研载板 + 独立 MCU
          |
          | 千兆以太网
          v
工控机 HMI / 数据归档
          |
          v
机器人、PLC、外部分析平台
```

核心分工如下：

- 三路相机负责同步采集胶路图像。
- 独立 MCU 负责硬件触发、LED 频闪、IO、看门狗和设备状态监测。
- RK3588 负责图像采集、传统视觉量测、神经网络推理、缺陷判定和结果封装。
- 工控机负责示教、配方、实时监控、图像回放、报表和外部系统接口。
- 工控机或工业网关负责与机器人、PLC 和外部分析平台对接。

## 3. 首版目标和范围

首版重点验证一条完整的技术主链路：

```text
三路图像稳定 -> 胶条可测量 -> 缺陷可判定 -> 结果可追溯 -> 设备可连续运行
```

建议首版主要指标如下：

| 项目 | 首版目标 |
|---|---|
| 相机数量 | 3 路 |
| 单相机分辨率 | 1280 x 960 或 1280 x 1024 |
| 快门类型 | 全局快门 |
| 采集帧率 | 30 fps |
| 检测视野 | 约 100 x 80 mm |
| 宽度重复性 | 实验室先达到约 0.2 mm |
| 最小宽度偏差 | 约 0.5 mm 起步 |
| 三相机同步 | 首版曝光偏差小于 1 ms，产品目标小于 100 us |
| 端到端延迟 | 首版小于 150 ms，产品目标典型小于 50 ms |
| 对外接口 | 千兆以太网 |
| 连续运行 | 首版 8 小时无掉线、无漏帧 |

首版优先覆盖断胶、过宽、过窄和位置偏差，同时保留多胶、气泡等缺陷的
扩展能力。RGB 三色照明、2K 分辨率、自动示教、多车型配方和复杂联网功能
放在主检测链路稳定之后。

## 4. 关键技术决策

| 决策 | 方案 | 主要原因 |
|---|---|---|
| RK3588 核心板 | 采用量产 SoM，自研载板 | 避免第一版承担 DDR、电源时序、BGA 和核心 BSP 风险 |
| 相机 | 先用成熟 MIPI 相机模组 | 优先验证采集、同步、算法和整机，再考虑相机子板 |
| 传感器内部传输 | 短 FPC 和 MIPI CSI-2 | 满足三路相机带宽，同时控制信号完整性风险 |
| 对外传输 | 首版采用千兆以太网 | 检测结果和压缩图不需要裸 MIPI 或同轴链路 |
| 实时控制 | 独立 MCU 负责触发和 IO | Linux 不适合直接承担安全相关的硬实时输出 |
| 算法路线 | 传统视觉量测加深度学习复判 | 胶宽和位置需要可解释、可追溯的物理量测 |
| 模型部署 | PC 训练，RKNN 推理 | 兼顾模型迭代效率和边缘端运行约束 |
| 现场总线 | 使用成熟网关模块 | 降低 Profinet、DeviceNet 和 EtherNet/IP 认证成本 |

## 5. 各阶段工作安排

以下周期按 4 至 6 人跨职能团队估算。阶段可以并行，周期不能直接相加。

| 阶段 | 参考周期 | 主要工作 | 关键交付物 |
|---|---:|---|---|
| P0 需求冻结与产品拆解 | 3-5 周 | 明确检测对象、缺陷类型、精度、视野、节拍、接口和产品形态；收集真实工件与胶型信息 | 需求文档、缺陷字典、验收指标、系统架构和风险清单 |
| P1 论文装置复现 | 8-12 周 | 先完成单相机、镜头和 LED 成像基线，再扩展到三相机；验证硬件触发、频闪和图像一致性；采集首版数据 | 三相机稳定成像、触发时序图、图像数据集和可行性结论 |
| P2 光学与机械基线 | 6-10 周 | 优化三相机约 120 度布置、工作距离、视场重叠和 LED 环形照明；制作可换镜头的样机；建立标定流程 | 光学方案、灯板和散热方案、传感器头 v0、标定程序 |
| P3 算法与数据闭环 | 12-16 周 | 建立图像质量检查、ROI 定位、胶条分割、骨架提取、宽度和位置测量基线；使用深度学习处理反光、孔洞和复杂背景 | 可重复运行的算法工程、逐类检测指标、标注规范和模型卡 |
| P4 工控机控制软件 | 12-16 周 | 实现触发、采集、推理、判定、显示、存储、回放和报表的完整闭环；完成示教、配方、权限和断线重连 | PC 端可操作样机、通信协议、配方格式和演示工位 |
| P5 RK3588 与 MIPI 台架验证 | 8-12 周 | 先验证一路，再验证三路 MIPI 采集；完成设备树、V4L2、硬件触发、零拷贝链路、RKNN 部署和延迟测试 | 三路 MIPI 台架、RKNN 模型，以及帧率、延迟和温度报告 |
| P6 自研载板 EVT | 12-18 周 | 集成 RK3588 SoM、三路 MIPI、独立 MCU、24 V 输入保护、照明控制、以太网、存储和调试接口 | 原理图、PCB、BOM、EVT 样机、电源和链路测试报告 |
| P7 产品软件与 DVT | 16-24 周 | 将实验室程序拆成可部署的设备服务；完善本地存储、断点续传、看门狗、升级回滚、自检和异常恢复 | DVT 软件、设备接口、升级和诊断机制、长时间运行报告 |
| P8 可靠性和认证 | 16-24 周 | 完成高低温、振动、电源、EMC、防护、LED 光衰、网络异常和故障注入等测试 | 可靠性报告、认证准备材料、故障降级和维护流程 |
| P9 现场试点与量产 | 12-24 周 | 在真实产线试点，统计漏报、误报、停机和人工复核情况；完成小批试产、出厂测试和文档 | 现场验收报告、PVT 样机、生产测试工装和量产版本 |

## 6. 阶段之间的关系

项目的主线可以概括为四个层次：

1. **技术复现层：P0-P2**

   明确检测对象和验收标准，完成论文装置复现，把“能拍到”提升为“每次都能
   稳定拍到”。

2. **检测能力层：P3-P4**

   建立可解释的视觉量测基线，形成完整的数据闭环，再用工控机完成检测业务
   流程，证明方案具备实际检测能力。

3. **边缘工程层：P5-P7**

   将检测能力迁移到 RK3588，验证三路 MIPI、RKNN 和实时链路，再通过自研
   载板与产品软件完成工程样机。

4. **产品化层：P8-P9**

   通过环境、可靠性和认证测试，并在真实产线试点，验证误报、漏报、维护和
   生产一致性，最终进入小批试产和量产。

## 7. 阶段评审门槛

| 门槛 | 需要回答的问题 | 不通过时的处理 |
|---|---|---|
| G0 需求冻结 | 缺陷、视野、精度、节拍和接口是否已经量化 | 补充客户样件和验收标准 |
| G1 论文复现 | 三相机和频闪能否稳定得到可用图像 | 暂停算法和 PCB 投入 |
| G2 光学基线 | 图像质量、照度和标定是否稳定 | 调整镜头、相机角度、灯板或机械结构 |
| G3 算法基线 | 真实验证集是否达到最低检测能力 | 扩充数据并调整算法方案 |
| G4 边缘链路 | 三路 MIPI、RKNN 和网络是否稳定 | 更换相机模组、BSP 或降低首版规格 |
| G5 EVT | 自研载板是否能够重复启动和稳定运行 | 不进入 DVT，先解决硬件根因 |
| G6 DVT | 产品软件、异常恢复和可靠性是否闭环 | 延后现场试点 |
| G7 现场试点 | 真实产线的误报、漏报和维护是否可接受 | 返回模型、光学或机械阶段继续迭代 |

## 8. 汇报时建议强调的重点

1. **先降低技术风险，再增加产品功能。**

   先用成熟相机模组和 RK3588 SoM 验证整机，再考虑自研相机子板和自研核心板。

2. **胶宽测量不能只依赖端到端神经网络。**

   采用传统视觉、几何量测和标定链路保证结果可解释、可追溯，再使用深度
   学习处理反光、阴影、孔洞和复杂背景。

3. **阶段之间设置明确的淘汰点。**

   如果三相机、MIPI 或成像链路没有跑通，就不进入载板和产品化投入。

4. **首版范围要收敛。**

   优先完成三路成像、胶条可测、缺陷可判、结果可追溯和设备可连续运行。

## 9. 近期工作建议

如果老师询问项目近期如何启动，建议先完成以下工作：

1. 收集 20 至 50 个真实工件样本，建立断胶、过宽、过窄、位置偏差等缺陷
   字典。
2. 采购一台相机、一支匹配镜头、一组红光 LED 和可调恒流源。
3. 建立 24 V 输入到相机触发、LED 频闪和曝光的时序测试台。
4. 完成约 100 x 80 mm 视野的镜头选型、单相机标定和尺寸重复性测试。
5. 采集正常和典型缺陷样本，建立首版算法评估脚本与标注格式。
6. 扩展到三相机采集，测量同步偏差、端到端延迟和测量误差。
7. 选择 RK3588 开发板和具有驱动源码的 MIPI 相机模组，形成硬件选型
   清单，再决定是否进入 P5。

## 10. 一句话总结

本方案以论文复现为技术起点，以三相机同步成像和可解释视觉量测为基础，
通过 RK3588 边缘计算实现涂胶缺陷在线检测，再按照“先验证、后定制、最后
产品化”的顺序逐步降低硬件、算法和现场集成风险。

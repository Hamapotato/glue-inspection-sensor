# P0 规范：指标口径、数据规范与假设登记

> 状态：草案（P0 交付物）
> 目的：在写任何训练/评测代码之前，先把"怎么算成功"和"数据长什么样"定死。
> 为什么必须先做：论文的指标口径与常规认知不同（见 §1 备注列），先对齐口径，后面才不会出现"跑出 99% 却没人认"的情况。

## 1. 指标定义

所有指标由 `algo/metrics.py` 统一实现，报告必须写清用了哪个定义。

| # | 指标 | 符号 | 定义 | 论文对照 | 备注（易错点） |
|---|---|---|---|---|---|
| M1 | RoI 定位平均 IoU | `meanIoU` | 对测试集每张图计算 `IoU(预测框, GT框)`，再取算术平均 | 摘要"平均 IoU 99%" | **不是 mAP**；表 5-2 的 AP 不能当目标 |
| M2 | 反光样本召回 | `recall_sample` | 检出数 / 反光样本总数（一张图至少 1 个框即算检出） | "77 张检出 75 张，97%" | **样本级**，不是像素级 |
| M3 | 反光框 IoU | `iou_reflection` | 逐图 `IoU(预测框, GT框)` 的平均 | 表 3-4（74.22~93.37%） | 与 M2 是两回事，报告要分开写 |
| M4 | 宽度平均绝对误差 | `mae_mm` | `mean(|计算宽度 − 人工卡尺宽度|)` | 0.23 mm | 真值是人工实测，不是"理论 10±1" |
| M5 | 宽度误差标准差 | `std_mm` | 上式的总体标准差 | 0.25 mm | 说明离散程度 |
| M6 | 宽度最大误差 | `max_mm` | `max(|误差|)` | 0.39 mm | 单点最坏情况 |
| M7 | 单帧纯推理耗时 | `latency_ms` | 预处理→定位→分割→量测的墙钟时间，p50/p95 | 约 80 ms（反光分支） | 不含采集与存图 |
| M8 | 端到端耗时 | `e2e_ms` | 触发→输出结果（含采集） | 论文未给 | 30 fps 必须用这个证明 |
| M9 | 缺陷检出（小样本） | — | 断胶/过窄/过宽的定性判定 | 表 5-4 仅 3 条过窄样本 | 样本太少，只做定性，不报百分比 |
| M10 | 误报率 | `fpr` | 正常样本被判缺陷的比例 | 论文未给 | 需自定义门限 |

**统计口径**：所有指标基于固定测试集，测试集一经确定不得再动；换测试集必须在报告里注明版本。

## 2. 数据集划分规则

1. **按工件/批次划分**，不按帧随机划分。同一条胶条的多帧、同一工件的多相机图，只能落在同一个集合里。
2. 建议比例：train : val : test = 7 : 1.5 : 1.5，且 test 中必须包含困难样本（反光、阴影、断胶、过窄）。
3. 反光检测的特殊要求：**反光样本要整组划分**（同一反光工位/同一光照条件归入同一侧），否则召回会被高估。
4. 划分结果落盘为 `data/splits/{train,val,test}.txt`，每行一个 `image_id`，随 commit 一起提交（不含图像本身）。

## 3. 标注规范

### 3.1 RoI 框（B1 用）

- 类别：单类 `glue`。
- 框法：包住整条可见胶条的最小外接矩形；胶条被图像边界截断时，框到边界为止。
- 精度：框边与胶条外缘的距离误差 ≤ 3 px。
- 一图多段（断胶）：每段一个框，不合并。

### 3.2 反光框（B2 用）

- 类别：单类 `reflection`。
- 框法：包住反光高亮区域的最小外接矩形。
- **细长反光必须单独标注**（这正是论文加 5 层特征层的动机，图 3-19/3-33）。
- 一图多个反光区域 = 多个框；反光与胶条重叠不影响标注。
- 标注存疑时标 `ignore=1`，评测时跳过该图。

### 3.3 胶条掩膜（C 组评估用，不参与训练）

- 二值 PNG，与图像同名；前景 255，背景 0。
- 用于评估 Otsu 分割与 BFS 面积，**不用于训练任何模型**。

### 3.4 宽度真值（C7 验收用）

每条记录至少包含：

| 字段 | 说明 |
|---|---|
| `object_id` | 工件/胶段编号，与图像关联 |
| `position_mm` | 沿胶条方向的位置（可选，用于定位对应帧） |
| `width_manual_mm` | 游标卡尺读数 |
| `repeat_1/2/3` | 同一位置重复测 3 次，取均值 |
| `operator` | 测量人 |
| `tool` | 量具型号与分度值 |
| `timestamp` | 测量时间 |

### 3.5 缺陷标签

`OK` / `BROKEN` / `TOO_NARROW` / `TOO_WIDE` / `REFLECTION`，允许多标签（如 `TOO_NARROW` + `REFLECTION`）。

## 4. 数据目录与 manifest

```
data/
├─ raw/<date>/<camera_id>/<image_id>.png     # 原图，不裁剪
├─ labels/
│  ├─ roi/<image_id>.json                    # {"boxes":[[x1,y1,x2,y2],...]}
│  ├─ reflection/<image_id>.json
│  └─ mask/<image_id>.png
├─ splits/{train,val,test}.txt
└─ manifest.csv
```

`manifest.csv` 字段（采集参数必须记录，否则无法复现分布）：

```
image_id, path, camera_id, object_id, batch, timestamp,
exposure_us, gain_db, pixel_format, working_distance_mm,
light_mode, glue_color, label, ignore
```

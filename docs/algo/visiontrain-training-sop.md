# VisionTrain 胶条/背景分割训练 SOP

> 目标：训练当前算法主线的胶条像素分割模型
> 类别：`background`、`glue`
> 数据：`visiontrain-glue-binary-v5-500`
> 软件：VisionTrain 2.3、VisionMaster 4.4
> 边界：合成数据只用于流程验证和预训练，不能作为真实验收

## 1. 先理解模型负责什么

本模型只回答一个问题：图中哪些像素是 `glue`，哪些是 `background`。

```text
输入图像
  -> VisionTrain 分割模型
  -> glue/background 概率图或掩膜
  -> 二值化与形态学后处理
  -> 沿胶条放置旋转扫描矩形
  -> 每个矩形内找左右边缘点
  -> 左右边缘点中点连成中心曲线
  -> 断胶、过窄、过宽、宽窄不一致、弯曲判定
```

断胶、宽窄和弯曲不是分割类别。断口在掩膜中必须保持为背景，宽窄和弯曲由
后续扫描窗测量。把缺陷设成额外类别会偏离当前主线。

## 7. 数据划分

本轮应保留生成器提供的分组：

```text
train 350 / val 75 / test 75
```

同一 `object_id` 的所有帧只能出现在一个集合。当前 `frames_per_object=1`，
但仍应检查 `manifest.csv` 的分组。

不要习惯性点击“自动划分”覆盖已有划分。若 VisionTrain 没有读取分组：

1. 先记录当前实际分组；
2. 删除本轮导入的数据，不删除源数据；
3. 重新导入并确认导入器支持 `dataset.json` 的 `image_type`；
4. 仍不支持时，才在 VisionTrain 内做一次 70/15/15 自动划分。

自动划分只能用于这批独立合成样本的流程验证。真实相机数据必须按工件、批次
或采集对象分组，不能逐帧随机拆分。

验证集用于选择训练轮次和阈值；测试集只在模型方向确定后使用一次。测试集不能
因为效果不好而反复替换。

### 8.1 GPU/CPU 必须和部署一致

选择 GPU 训练时，导出模型需要 GPU 推理运行时。若最终产线电脑没有匹配的
NVIDIA GPU，或者 VisionMaster 只能运行 CPU 模块，就应改为 CPU 训练/导出，
或者同时产出 CPU 模型另行比较。不能把 GPU 训练模型直接当作 CPU 模型使用。

### 8.2 开始训练

1. 填写模型名称 `glue_bg_seg_syn500_v5_vm440_gpu_v001`。
2. 设置模型生成目录。
3. 检查训练集和测试集数量。
4. 单击“训练参数推荐”时，仅把它作参考，仍按上表检查平台、版本和分辨率。
5. 开始训练。
6. 立即保存训练参数截图或配置导出。

训练过程中只观察，不用测试集调参：

- 训练 Loss 是否总体下降；
- 验证 Loss 是否同步下降；
- 训练 Loss 下降而验证 Loss 明显上升，可能过拟合；
- Loss 长期不下降，优先检查标注错位、纯背景图误处理、类别配置；
- 图像在 UI 中是否仍为完整视野，不能在训练时被隐式裁边。

目前已有首轮可运行的 VM 440 CPU 模型，但还没有冻结的分割指标和真实数据
指标；不得预填或推测 IoU、召回率、精确率和耗时。

## 9. 测试和评估

### 9.1 只做一次正式测试

1. 打开“模型测试”或“测试评估”。
2. 选择当前模型和最新版本。
3. 推理模式与训练时平台保持一致：本轮为 GPU。
4. 测试范围选择“测试集”，不要使用全部 500 张汇报。
5. 初始阈值使用 `0.5`；若界面有 IoU 阈值，也先使用 `0.5`。
6. 运行测试并保存结果。

### 9.2 必须记录

| 指标/现象 | 记录方式 |
|---|---|
| 胶条像素 IoU | 测试集均值 |
| 胶条像素召回率 | 测试集均值 |
| 胶条像素精确率 | 测试集均值 |
| 单帧平均耗时 | 同时记录 p50、p95（软件能导出时） |
| 断口补洞 | 逐张检查断胶测试样本 |
| 窄/宽边界 | 检查胶条两侧是否稳定 |
| 宽窄不一致 | 检查沿程变化是否被抹平 |
| 弯曲连续性 | 检查弯曲中心线是否中断 |
| 纯背景误分割 | 检查 77 类背景样本中的测试集部分 |

注意：VisionTrain 的“准确率”和本项目 P0 定义的像素 IoU 不是同一口径。
报告时必须写清指标名称，不能把分类准确率写成 IoU，也不能把像素指标写成
缺陷检出率。

### 9.3 视觉验收重点

- 断口应该是模型输出中的空洞，不能被后处理或模型系统性填平；
- 过窄、过宽的胶条仍应形成连续掩膜；
- 宽窄不一致区域不能被错误拆成断胶；
- 弯曲区域的掩膜和中心线不能断裂；
- 纯背景图不应出现大面积胶条概率；
- 模型边缘不应因为训练时缩放而系统偏移；
- 模型输出坐标必须与原 1440×1080 图像坐标一致。

以上通过只表示合成测试集可用，不表示真实产线验收通过。

## 11. 导出到 VisionMaster

1. 打开 VisionTrain“模型管理”。
2. 找到最终模型，确认目标平台为 VM、版本为 440、平台为 GPU。
3. 使用模型文件入口定位导出目录。
4. 确认生成了 VisionMaster 可加载的模型文件。不同版本可能生成
   `.mvbonnx`、`_Nvidia.bin`、`_Board.bin` 等配套文件。
5. 不要通过改后缀把普通 ONNX 当成 VisionMaster 模型。

VisionMaster 部署机需要匹配的运行时和授权。VisionTrain 导出的 `.bin`
不是可直接交给普通 ONNX Runtime 的通用模型；如果自研程序要直接推理，
必须使用 VisionMaster SDK 或另外完成独立模型转换与验证。

## 13. 接入当前 Python 主线

VisionMaster SDK 或自研部署包装器应输出与输入图同尺寸的胶条概率图或二值掩膜，
然后转换为：

```python
SegmentationOutput(
    mask=probability_or_binary_mask,
    source="visiontrain_glue_binary_v5_500",
    threshold=0.5,
    fallback=False,
    score_map=score_map,
)
```

再接主线：

```python
inspector = GlueInspector(cfg, segmenter=deployed_model, calib=calib)
result = inspector.run(image)
```

部署适配器尚未实现。接入时必须检查：

- 模型输入缩放后，输出是否正确映射回原图；
- 模型 ROI 坐标是否能还原为原图坐标；
- 概率图方向、宽高和通道是否与主线一致；
- 是否显式携带模型版本和阈值；
- 缺模型时不得静默回退到传统阈值算法。

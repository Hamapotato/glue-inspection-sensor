# RK3588 涂胶检测传感器开发路线

> 目标：以天津大学《基于机器视觉的车身涂胶在线检测系统研究》为技术起点，先完成可验证的传感器样机，再演进为基于 RK3588 的边缘计算产品，最终在检测能力、操作方式、数据追溯和现场集成上对标易思维 ISV 涂胶检测系统。
>
> 产品对标资料：[glue-inspection-product-brochure-v3.3.pdf](../references/source/glue-inspection-product-brochure-v3.3.pdf)
>
> 技术复现资料：[thesis-machine-vision-glue-inspection.pdf](../references/source/thesis-machine-vision-glue-inspection.pdf)

## 1. 项目定义

### 1.1 最终产品形态

传感器头部集成相机、镜头、照明、触发和 RK3588 计算板。三路相机通过传感器内部的 MIPI CSI-2 链路采集，RK3588 完成图像处理、神经网络推理、尺寸计算和缺陷判定。

传感器通过工业连接器向工控机输出：

- 胶条连续性、宽度、位置偏差、多胶、气泡等检测结果。
- 检测置信度、报警等级、相机编号、帧编号、配方编号和时间戳。
- 原图、检测叠加图、缺陷局部图和可选缩略图。
- 设备状态、温度、网络状态、日志和故障码。

工控机负责人机界面、示教、配方管理、图像留档、缺陷回放、报表和外部平台接口，不承担实时推理。

### 1.2 推荐系统边界

```text
相机 1 ─┐
相机 2 ─┼─ MIPI CSI-2 / 短 FPC ─ RK3588 SoM + 自研载板
相机 3 ─┘                         │
                                  ├─ NPU 推理、图像处理和判定
                                  ├─ 本地 NVMe 环形存储
                                  ├─ 隔离 24 V IO、硬件触发和 LED 同步
                                  └─ 千兆以太网
                                             │
                                    工控机 / HMI / 数据归档
                                             │
                              机器人、PLC、外部分析平台
```

MIPI 只用于传感器内部短距离传输。对外输出采用以太网，避免把裸 MIPI 信号拉出传感器。只有当未来需要在工控机保留多路高帧率原始视频时，才考虑 GMSL2、FPD-Link 或 1000BASE-T1 等同轴线方案。

### 1.3 关键架构决策

| 决策 | 建议 | 原因 |
|---|---|---|
| RK3588 核心板 | 采用量产 SoM，自研载板 | 避免第一版承担 LPDDR、电源时序、BGA 和核心 BSP 风险 |
| 相机 | 先使用带 Linux 驱动的成熟 MIPI 模组 | 先验证采集、同步、算法和整机，再决定是否自研裸 CMOS 板 |
| MIPI | 每路短 FPC，使用硬件触发 | 降低信号完整性风险和相机同步误差 |
| 对外接口 | 首版千兆以太网 | 检测结果和压缩图不需要裸 MIPI 或 GMSL 的带宽 |
| 实时控制 | RK3588 负责计算，独立 MCU 负责 IO、触发和看门狗 | Linux 不适合直接承担安全相关的硬实时输出 |
| 现场总线 | 使用经过认证的网关模块，不在 Linux 中自行实现全部协议栈 | Profinet、DeviceNet、EtherNet/IP 的组网和认证成本较高 |
| 训练与推理 | PC 训练，RKNN 部署 | 兼顾模型迭代效率和边缘端运行约束 |

## 2. 对标产品的能力拆解

产品册描述的是三相机 360 度涂胶检测传感器，主要能力如下。

| 产品能力 | 本项目的工程要求 | 首版复现是否必须 |
|---|---|---|
| 三相机 360 度拍摄 | 3 路相机同步曝光、固定角度、统一标定 | 必须 |
| LED 均匀照明 | 红色频闪照明，照度均匀性和热稳定可测 | 必须 |
| RGB 三色切换 | 红、绿、蓝照明独立控制并支持配方选择 | 产品阶段 |
| 断胶、多胶、过宽、过窄、位置偏差 | 缺陷分类、定位、尺寸和置信度输出 | 必须 |
| 胶条位置和灰度信息 | 输出像素坐标、物理坐标、宽度和灰度统计 | 必须 |
| 在线实时检测 | 采集到输出结果的端到端延迟可控 | 必须 |
| 手动/自动示教 | 配方、ROI、标准轨道、阈值和曝光可配置 | 论文复现后 |
| 双报警线 | 宽度上下限和预警/报警分级 | 产品阶段 |
| 缺陷回放 | 按零件、时间、相机、位置和缺陷类型查询 | 产品阶段 |
| 报表 | Excel、PDF 和统计趋势 | 产品阶段 |
| 外接分析平台 | 稳定的数据上传接口和断点续传 | 产品阶段 |
| 机器人/PLC 集成 | 24 V IO、以太网和现场总线网关 | 原型后 |
| 多车型配方 | 零件、车型、工位和胶路版本隔离 | 产品阶段 |
| 小体积传感器 | 外径约 150 mm，内孔 45/65 mm 两档 | 产品阶段 |
| 多工作距离 | 约 80-160 mm 覆盖多个镜头/安装变体 | 产品阶段 |
| 中文/英文界面 | 用户、权限、语言和单位可配置 | 产品阶段 |

产品册中的 5000 台销量、千万级图片和主机厂覆盖属于商业成果，不纳入开发验收。复现阶段需要复现的是检测原理、硬件架构和软件工作流。

## 3. 建议的产品指标

下列指标作为 v0.1 目标，进入 P0 需求评审后冻结。不同车型和胶型应建立独立验收阈值。

| 指标 | 样机目标 | 产品目标 |
|---|---|---|
| 相机数量 | 3 | 3，预留 1K/2K 两档 |
| 单相机分辨率 | 1280 x 960 或 1280 x 1024 | 1K 与 2K 产品按型号区分 |
| 快门 | 全局快门 | 全局快门 |
| 采集帧率 | 30 fps | 30 fps 起，可按工件速度配置 |
| 检测视野 | 约 100 x 80 mm | 由镜头和工作距离覆盖 80-160 mm |
| 宽度重复性 | 实验室先达到约 0.2 mm | 典型工况约 0.1-0.2 mm |
| 最小检出宽度偏差 | 约 0.5 mm 起步 | 由客户 CTQ 和标定结果定义 |
| 三相机同步 | 硬件触发，曝光 skew < 1 ms | 目标 < 100 us |
| 端到端延迟 | < 150 ms | 典型 < 50 ms，报警 < 100 ms |
| 连续运行 | 8 小时无掉线、无漏帧 | 24-72 小时稳定性试验 |
| 对外接口 | 千兆以太网 | 千兆以太网，可选现场总线网关 |
| 图像留档 | 原图、叠加图、缩略图 | 按配方和报警等级分级保存 |
| 工作温度 | 10-40 摄氏度实验室 | 0-50 摄氏度或客户规范 |
| 防护等级 | 首版不承诺 | 目标 IP65，外露连接器单独校核 |

相机运动速度约 1.1 m/s 时，1 ms 的相机间时间差对应约 1.1 mm 的位置差。产品阶段不能只依赖软件触发，必须使用同一硬件触发源、全局快门和固定曝光时序。

## 4. 总体开发流程

```text
P0 需求与对标
  -> P1 论文装置复现
  -> P2 光学、照明和机械验证
  -> P3 基础算法和数据闭环
  -> P4 工控机端控制软件
  -> P5 RK3588 + MIPI 台架原型
  -> P6 自研载板 EVT
  -> P7 产品软件与 DVT
  -> P8 环境、可靠性和认证
  -> P9 现场试点、PVT 和量产发布
```

P1 到 P4 可以先验证方案，但不建议在 3 路 MIPI 相机、驱动和触发尚未跑通前直接投主控板。

## 5. 分阶段工作包

### P0：需求冻结和产品拆解

目标：明确检测对象、缺陷定义、性能边界和产品形态，避免后续硬件与算法反复返工。

工作内容：

1. 建立缺陷分类表：断胶、过宽、过窄、多胶、位置偏差、气泡、边缘反光等。
2. 明确每个缺陷的判定方式、最小尺寸、连续长度、置信度和报警等级。
3. 采集目标工件、胶型、颜色、表面反光、机器人速度和现有胶枪信息。
4. 建立产品册到工程需求的追踪表。
5. 冻结首版 1K 传感器的光学指标、尺寸包络、接口和供电。
6. 建立硬件、软件、算法、机械共用的术语表和坐标系定义。

交付物：

- 产品需求文档。
- 缺陷分类与验收标准。
- 系统架构和接口控制文档。
- 风险清单及缓解计划。
- 首版实验 BOM 和采购清单。

退出条件：

- 三个典型缺陷能够在样图上人工一致标注。
- 视野、工作距离、节拍和精度已经量化。
- 明确首版采用 1 路验证、3 路集成，而不是一次完成全部产品功能。

### P1：论文装置复现

目标：用一台工业相机、镜头、LED 和工控机建立可信的图像基线，再扩展到三机位。

工作内容：

1. 购买一台相机和一支镜头，完成均匀性靶标和尺寸靶标拍摄。
2. 实测工作距离、视野、畸变、景深、照度和曝光时间。
3. 完成 24 V 输入到相机触发、LED 频闪的隔离和时序测量。
4. 增加第二、第三台相机，检查三路图像的时间一致性和空间角度。
5. 采集通过、断胶、宽度异常、多胶和位置偏移样本。
6. 记录相机、镜头、光源、曝光、增益、距离和环境光。
7. 对论文算法做最小可行复现，不直接照搬论文中的网络和参数。

交付物：

- 单相机光学测试报告。
- 三相机采集和触发时序图。
- 首版图像数据集及采集规范。
- 复现装置电气图、接线表和机械草图。
- 可行性结论：当前光学方案能否稳定看到目标缺陷。

退出条件：

- 三台相机能够由同一触发信号稳定启动。
- LED 只在曝光窗口工作，图像亮度重复性满足测量要求。
- 同一标准件的宽度重复测量和位置重复测量已经量化。
- 样图中可以明确分辨目标胶条和背景。

### P2：光学、照明和机械基线

目标：把“能拍到”提升为“每次都能稳定拍到”。

工作内容：

1. 优化三相机 120 度布置、镜头工作距离和相邻视场重叠。
2. 完成 LED 环形排布、漫射、遮光和角度设计。
3. 测量照度均匀性、LED 温升、光谱稳定性和频闪延迟。
4. 制作可换镜头的 3D 打印或铝制样机，保留线缆和散热空间。
5. 建立相机内参、畸变、三相机相对位姿和胶枪坐标到图像坐标的标定流程。
6. 定义标准件、标定靶和复检周期。

交付物：

- 光学设计说明和视场图。
- LED 灯板、恒流驱动和热设计。
- 传感器头 v0 机械结构。
- 标定程序和标定记录。
- 图像质量验收表。

退出条件：

- 三路视场覆盖预期区域，无明显盲区和重复遗漏。
- 靶标在全部工作距离内可清晰成像。
- LED 连续工作后亮度和色温漂移仍在允许范围内。
- 标准件重复拆装后的测量偏差可接受。

### P3：基础算法和数据闭环

目标：先建立可解释、可测量的传统视觉基线，再加入深度模型处理复杂场景。

建议算法分层：

1. 图像质量检查：曝光、过曝、欠曝、模糊、遮挡、丢帧。
2. ROI 和胶路定位：示教轨迹、模板定位或轻量网络。
3. 胶条分割和骨架提取：阈值、颜色或纹理分割、形态学处理。
4. 几何测量：连续性、面积、骨架长度、平均宽度、最大最小宽度。
5. 位置判定：与标准轨迹的法向距离和允许带比较。
6. 多胶与气泡：连通域、局部纹理和深度模型复判。
7. 深度学习检测：用于反光、阴影、孔洞、焊点、压胶、低对比度等复杂背景。
8. 不确定性输出：低置信度结果进入复判或人工确认，不静默判为通过。

数据工作：

- 按零件、车型、批次、光照和工位划分训练集、验证集和测试集，避免随机抽帧造成数据泄漏。
- 保存原图、ROI、标注、检测结果和人工复核结论。
- 建立困难样本回流和模型版本记录。
- 训练在 PC 完成，部署前做量化和 RKNN 精度回退测试。

交付物：

- 可重复运行的训练和评估工程。
- 缺陷分类、分割和测宽基线。
- 数据规范、标注规范和模型卡。
- 逐缺陷精确率、召回率、尺寸误差和延迟报告。

退出条件：

- 典型验证集上的误判和漏判满足 P0 目标。
- 每个缺陷都能追到原图、ROI、阈值或模型版本。
- 模型在未见过的批次和光照条件下没有明显失效。
- 判定结果可以在无 GPU 的推理环境中复现。

### P4：工控机端控制软件

目标：先完成完整的检测业务闭环，再把它迁移到边缘端。

建议采用两层架构：

- 设备侧服务：相机采集、推理、判定、IO、存储和设备 API。
- 操作端软件：配方、示教、监控、回放、报表和系统设置。

首个版本可采用 Python/PySide6 或 Qt/C++ 快速完成。产品版本建议保持稳定的 C++ 设备服务和 Qt 6 操作界面，训练工具继续使用 Python。

必须实现：

- 设备发现、连接、配置和断线重连。
- IDLE、READY、TRIGGERED、ACQUIRE、INFER、DECIDE、REPORT 和 FAULT 状态机。
- 手动示教、自动示教、一键导入导出。
- 车型、零件、胶路、ROI、曝光、阈值和报警等级配方。
- 实时结果区、工件总览区、通讯状态区和控制面板。
- 缺陷回放、按时间和零件查询、趋势统计。
- Excel/PDF 报表和外部平台上传接口。
- 权限、审计日志、中文/英文语言包。
- 故障码、日志导出和一键诊断包。

交付物：

- 可操作的 PC 端完整流程。
- 设备通信协议和 API 文档。
- 配方文件格式和版本迁移规则。
- 用户操作手册和演示工位。

退出条件：

- 一次完整流程可以从触发、采集、推理、判定、显示、存储到回放闭环。
- 异常断网、相机掉线和软件重启后可以恢复。
- 操作人员无需启动开发环境即可完成示教和检测。

### P5：RK3588 和 MIPI 台架原型

目标：使用 RK3588 开发板和成熟 MIPI 相机模组，证明边缘计算链路可行。

先做一路，再做三路。不要同时引入自研载板、裸 CMOS、三相机同步和模型移植。

工作内容：

1. 选择 RK3588 SoM/开发板、Linux BSP 和可公开驱动源码的 MIPI 相机模组。
2. 完成设备树、I2C、时钟、复位、MIPI D-PHY 和 V4L2/media controller 配置。
3. 验证单路 RAW 采集、曝光、增益和外部触发。
4. 验证三路 CSI 端口、FPC 长度、带宽和多路采集。
5. 建立 V4L2 dma-buf 到 RGA/NPU 的零拷贝链路。
6. 将基础算法和检测模型转换为 RKNN。
7. 统计采集、预处理、推理、后处理、编码和网络延迟。
8. 建立 24 小时掉帧和温升测试。

相机模组准入条件：

- 全局快门优先。
- 黑白版本可外触发，并提供频闪输出或同步信号。
- MIPI CSI-2 D-PHY 接口，驱动源码和设备树可获取。
- 像素格式、帧率、曝光范围和触发时序可配置。
- 镜头座、法兰距、靶面和图像中心可校准。
- 有明确生命周期和供货计划。

交付物：

- RK3588 相机适配说明。
- 单路和三路采集日志。
- 延迟、帧率、CPU、NPU、温度和内存报告。
- RKNN 模型和精度对比表。

退出条件：

- 三路相机稳定采集目标帧率，无 USB 方案中的 Hub 枚举问题。
- 三路触发顺序和曝光 skew 可测量。
- 低置信度、异常帧和掉帧能够上报。
- 模型部署后精度下降在允许范围内。

### P6：自研载板 EVT

目标：把 RK3588 SoM、三路 MIPI、照明、IO、存储和网络集成到传感器内部。

首版载板应包含：

- RK3588 SoM 插座和电源时序。
- 3 路 MIPI CSI-2 FPC 连接器。
- 传感器电源、参考时钟、I2C、复位和触发信号。
- 独立 MCU：触发、PWM、灯板、IO、温度和看门狗。
- 24 V 输入保护、软启动、反接保护、TVS 和 EMI 滤波。
- 12 V、5 V、3.3 V、1.8 V 等电源域。
- 千兆以太网 PHY、隔离或保护、M12 X-code 接口。
- 24 V 触发输入、报警输出、状态灯和调试口。
- NVMe 或 eMMC 存储、RTC、温度传感器和风扇接口。
- 烧录、恢复和串口调试接口。

PCB 要求：

- 建议 8 层板，完整地平面，MIPI 差分阻抗按模组和数据手册要求控制。
- MIPI 走线尽量短，少换层，差分对内等长，避免跨平面。
- 以太网差分阻抗按 100 欧姆控制。
- 相机供电和 LED 大电流回路与 SoM、MIPI、以太网分区布置。
- 每个相机连接器附近放置去耦、ESD 和必要的保护器件。
- 灯板与主控板分板或设置明确热隔离。
- 所有连接器和 FPC 增加防呆、锁扣和应力释放。

交付物：

- 原理图、PCB、BOM、装配图和 DFM 检查记录。
- 电源时序、上电浪涌、掉电和复位测试。
- MIPI 眼图或链路误码测试结果。
- 三路相机同时运行报告。

退出条件：

- 5 块以上 EVT 板都能独立启动和识别相机。
- 三路相机运行 72 小时无掉线、无持续误码。
- 24 V 输入波动、反接、瞬态和 ETH 热插拔不会损坏设备。
- 温度、功耗和结构包络满足样机要求。

### P7：产品软件和 DVT

目标：把实验室程序变成可部署、可升级、可维护、可诊断的产品软件。

工作内容：

1. 设备服务拆分为采集、推理、IO、存储、网络和系统管理模块。
2. 采用有版本的 IPC 协议，结果消息包含完整追踪字段。
3. 本地保存环形缓冲，优先保存报警原图、叠加图和缺陷局部图。
4. 上传支持断点续传、去重、失败重试和磁盘配额。
5. 建立设备时钟同步、序号和防重复判定机制。
6. 增加看门狗、进程守护、崩溃转储和日志分级。
7. 升级包签名、回滚和兼容性检查。
8. 建立相机、LED、温度、风扇、存储和网络自检。
9. 所有配方、模型和标定文件纳入版本管理。
10. 完成 HMI 与设备服务联调及自动化回归测试。

建议对外协议：

- 控制命令和配置：HTTP/gRPC。
- 实时结果：WebSocket 或轻量级二进制消息。
- 图像：独立文件或分块上传，不把大图塞入 JSON。
- 时间字段统一使用设备时间、工控机时间、单调时钟和触发序号。
- 每条结果包含传感器 ID、配方版本、模型版本、固件版本和标定版本。

退出条件：

- 断网后设备继续检测，网络恢复后自动补传。
- 软件升级失败能回滚。
- 断电后不会留下不可恢复的存储状态。
- 连续运行 72 小时无内存泄漏和进程失控。

### P8：可靠性和认证

目标：从“研发样机”进入“可在工业现场连续运行”的状态。

测试项目：

- 高低温工作和存储。
- 温度循环、热冲击和长时间温升。
- 振动、冲击、跌落和运输包装。
- 电源波动、瞬断、浪涌、静电和反接。
- EMC 辐射和传导发射、抗扰度。
- LED 光衰和频闪稳定性。
- 线缆弯折、插拔寿命和连接器锁紧。
- 防尘防水和清洗剂兼容性。
- 网络丢包、延迟、重连和广播风暴。
- 相机遮挡、镜头污染、失焦和光源故障检测。
- 软件故障注入、掉电恢复和看门狗测试。

开发过程中应同步完成 DFMEA、硬件评审、软件评审和关键器件替代评估。产品认证目标需按销售区域和客户要求另行确定，常见方向包括 CE、FCC、RoHS 和客户企业标准。

退出条件：

- 测试计划和报告闭环。
- 所有关键故障都有检测方式、降级策略和维修流程。
- 物料、工艺、测试和软件版本可以追溯到单台设备。

### P9：现场试点、PVT 和量产发布

目标：在真实产线验证检测能力、操作方式、维护方式和生产一致性。

工作内容：

1. 选择一条有代表性的产线做 4-8 周试点。
2. 记录每班次检测量、漏报、误报、停线和人工复核。
3. 建立客户现场标定、换型、清洗和维护 SOP。
4. 统计常见故障、平均修复时间和备件消耗。
5. 根据现场数据回流模型，建立固定阈值和模型冻结流程。
6. 完成 PVT 小批试产，验证装配节拍、测试节拍和良率。
7. 建立出厂测试台、标定台、老化台和维修工装。
8. 冻结硬件、固件、模型、配方格式和文档。

退出条件：

- 现场验收指标达到合同或 P0 定义。
- 连续生产阶段没有未定义的安全风险。
- 出厂测试和现场复检结果一致。
- 备件、培训、手册和远程支持流程齐备。

## 6. 软硬件详细设计要点

### 6.1 采集与时序

推荐使用独立 MCU 产生统一触发，同时控制 LED：

```text
24 V 工位触发
    -> 隔离输入
    -> MCU 时序
       -> 相机 1/2/3 外触发
       -> LED 频闪
       -> RK3588 帧同步信号
```

MCU 还负责：

- 触发超时和重复触发过滤。
- LED 开路、短路和过温检测。
- 相机复位和连接状态。
- 独立看门狗。
- 报警输出和急停状态。

### 6.2 MIPI 和图像链路

建议链路：

```text
MIPI CSI-2
  -> RK3588 MIPI RX
  -> V4L2 采集
  -> dma-buf
  -> RGA
  -> RKNN / 传统视觉
  -> 叠加和编码
  -> 本地存储 / 以太网
```

关键要求：

- 相机 RAW 数据不做无意义的重复内存拷贝。
- 三路图像使用统一的帧编号和触发编号。
- 图像时间戳同时记录触发时间、曝光起止时间和接收时间。
- 发生丢帧时必须输出明确故障，不可自动跳过。
- 模型输入尺寸、色彩空间和量化参数必须版本化。

### 6.3 网络和数据协议

首版对外使用千兆以太网。建议结果消息至少包含：

- `message_id`
- `sensor_id`
- `cycle_id`
- `trigger_id`
- `recipe_id`
- `model_version`
- `firmware_version`
- `calibration_version`
- `timestamp`
- `camera_ids`
- `overall_result`
- `defect_list`
- `image_uri_list`
- `diagnostic_status`

缺陷项至少包含：

- 缺陷类型。
- 相机编号。
- 图像坐标和工件坐标。
- 胶条宽度或长度。
- 置信度。
- 预警或报警等级。
- 关联图像编号。

图像建议分级保存：

- 通过：缩略图或按比例抽样。
- 预警：原图、叠加图。
- 报警：原图、叠加图、缺陷局部图和处理参数。
- 设备异常：调试日志、最后一帧和状态快照。

### 6.4 CMOS 自研顺序

建议分三步：

1. 使用成熟 MIPI 相机模组完成整机验证。
2. 保持同一 CMOS，设计相机子板，验证供电、时钟、MIPI、连接器和驱动。
3. 将相机子板与主控载板、镜头座和灯板进行结构、热和 EMC 联合优化。

裸 CMOS 自研的准入条件：

- 数据手册、封装、引脚和参考电路完整。
- 电源时序、时钟、复位和 MIPI 参数明确。
- 有 Linux/V4L2 驱动参考或可维护的驱动方案。
- 有可采购的镜头座、滤光片和校准工装。
- 有 MIPI 信号完整性和量产测试能力。

若上述条件不满足，应继续使用开放驱动的相机模组，不应把裸 CMOS 设计作为整机可行性的前置条件。

### 6.5 算法产品化

模型开发顺序：

1. 传统视觉和几何量测建立基线。
2. 规则算法覆盖稳定、可解释的场景。
3. 深度学习处理反光、阴影、孔洞、压胶和低对比度。
4. 使用多任务或级联模型减少重复推理。
5. 用 RKNN 量化和算子替换，比较 PC 与板端输出。
6. 用困难样本、跨批次样本和负样本做回归。
7. 对低置信度、遮挡和图像质量异常设置拒判策略。

不建议只用一个端到端模型同时完成定位、测宽和缺陷分类。胶宽是需要可追溯物理量测的任务，应保留标定链路和几何计算过程。

## 7. 测试和验收体系

### 7.1 分层测试

| 层级 | 测试内容 | 通过标准 |
|---|---|---|
| 单元测试 | 标定、坐标变换、协议解析、状态机 | 覆盖率满足项目门槛 |
| 算法测试 | 每个缺陷类别、图像质量、跨批次 | 达到逐类指标 |
| 硬件测试 | 电源、MIPI、Ethernet、IO、热 | 无异常复位和持续误码 |
| 系统测试 | 三相机采集到工控机显示 | 完整闭环、可恢复 |
| HIL 测试 | 模拟机器人触发、网络抖动、掉线 | 状态和报警正确 |
| 环境测试 | 温度、振动、EMC、IP | 达到目标标准 |
| 现场测试 | 真实胶枪、工件、节拍和工况 | 客户验收指标达标 |

### 7.2 关键统计指标

- 断胶漏检数。
- 多胶误检数。
- 过宽/过窄漏检数。
- 位置偏差漏检数。
- 每幅图的误报率。
- 每个工件的总错误率。
- 宽度绝对误差和重复性。
- 从触发到结果的 P50、P95、P99 延迟。
- 每班次丢帧、重启和网络重连次数。
- 每千次检测的人工干预次数。

### 7.3 出厂测试

每台设备至少完成：

1. 电源、短路和反接保护测试。
2. 三路相机枚举、对准和坏点检查。
3. MIPI 链路和丢帧测试。
4. LED 亮度和频闪测试。
5. 标准靶标标定和尺寸复检。
6. 网络吞吐和断开重连测试。
7. 固件、模型、配方和序列号烧录。
8. 连续老化测试。
9. 配置和测试记录归档。

## 8. 人员配置和周期

推荐最小团队：

- 1 名硬件工程师：电源、载板、MIPI、EMC、DFM。
- 1 名嵌入式工程师：BSP、相机驱动、V4L2、RKNN Runtime、IO。
- 1-2 名视觉算法工程师：标定、传统视觉、数据、模型和部署。
- 1 名软件工程师：设备服务、协议、UI、回放、报表。
- 1 名机械/测试/质量角色：结构、夹具、可靠性、客户验收。

周期判断：

- 论文装置和基础算法样机：约 6-10 个月。
- RK3588 + MIPI 三相机功能样机：在上述基础上增加 4-8 个月。
- 达到可批量交付的产品状态：4-6 人团队通常需要 18-30 个月。
- 单人完成软件、算法、硬件、机构和认证，周期应按团队方案乘以 1.5-2.5，不能按纯开发工时估算。

上述周期不包含销售人员、售后服务网络和客户产线改造时间。

## 9. 主要风险和淘汰点

| 风险 | 后果 | 缓解措施 | 淘汰条件 |
|---|---|---|---|
| 相机传感器与论文参数不一致 | 镜头、视野和标定错误 | 购买前核对正式数据手册和实物 | 型号、传感器、靶面和驱动无法确认 |
| MIPI 相机驱动不可维护 | 项目卡在采集层 | 先选有 Linux 驱动源码的模组 | 三路无法稳定出图 |
| 三相机同步不足 | 360 度结果错位 | MCU 统一触发，测量 skew | skew 无法满足运动精度 |
| RAW 数据带宽或内存拷贝过大 | 延迟和丢帧 | dma-buf、RGA、降低无用帧率和分辨率 | 优化后仍低于目标节拍 |
| LED 热漂移 | 宽度和对比度不稳定 | 恒流、频闪、热隔离和温度补偿 | 连续运行无法稳定成像 |
| 反光和复杂背景 | 误判和漏判 | 多照明、偏振、深度模型和复判 | 真实验证集长期不能达标 |
| 自研 RK3588 核心板 | 启动、DDR、BSP 风险失控 | 采用 SoM，自研载板 | 载板仍出现基础启动问题 |
| 直接自研裸 CMOS | 驱动、供电、封装和量产失败 | 先模组后子板 | 无参考设计和驱动资源 |
| 现场总线认证不足 | 无法接入机器人/PLC | 使用成熟网关模块 | 目标协议无法通过客户验证 |
| 模型迭代没有版本控制 | 结果不可追溯 | 模型、配方、标定、固件全版本化 | 无法复现历史判定 |
| 温升和结构过紧 | 相机噪声、掉线和凝结 | 热仿真、风道、隔热和温控 | 0-50 摄氏度无法稳定 |
| 只做实验室样机 | 现场误报、维护困难 | 早做现场试点和 DFM | 现场 4-8 周无法通过 |

## 10. 阶段评审门槛

| Gate | 必须回答的问题 | 不通过时的动作 |
|---|---|---|
| G0 需求冻结 | 缺陷、视野、精度、节拍、接口是否量化 | 补客户样件和验收标准 |
| G1 论文复现 | 三相机和频闪能否稳定得到可用图像 | 暂停算法和 PCB 投入 |
| G2 光学基线 | 图像质量、照度和标定是否稳定 | 修改镜头、角度、灯板或机械 |
| G3 算法基线 | 真实验证集是否达到最低检测能力 | 扩充数据和调整方案 |
| G4 边缘链路 | 三路 MIPI、RKNN 和网络是否稳定 | 更换模组、BSP 或降低首版规格 |
| G5 EVT | 自研载板是否可重复启动和运行 | 不进入 DVT，先解决硬件根因 |
| G6 DVT | 产品软件、异常恢复和可靠性是否闭环 | 延后现场试点 |
| G7 P9 试点 | 真实产线的误报、漏报和维护是否可接受 | 返回模型或光学阶段 |

## 11. 前 30 天行动计划

### 第 1 周

- 确认首版只做 1K 三相机、红色频闪和断胶/宽度/位置偏差。
- 收集 20-50 个真实工件样本，建立缺陷字典。
- 核对相机正式数据手册、传感器型号、靶面和驱动资源。

- 完成 100 x 80 mm 视野的初始镜头选型。

### 第 3 周

- 完成单相机标定和尺寸靶标测试。
- 采集正常、断胶、宽度异常和位置偏移样本。
- 建立首版算法评估脚本和标注格式。

### 第 4 周

- 用 USB 方案扩展到三相机，验证 360 度采集。
- 输出可行性报告、实测延迟和误差数据。
- 选择 RK3588 开发板/CB 系列 MIPI 相机模组，形成硬件选型清单。
- 决定是否进入 P5，而不是此时直接投载板。

## 12. 首版不建议同时实现的功能

以下功能应在主检测链路稳定后增加：

- RGB 三色照明。
- 自动示教。
- 多车型配方管理。
- 2K 高分辨率版本。
- 外接分析平台。
- 1000BASE-T1 或其他同轴传输。
- 自研裸 CMOS 相机板。
- Wi-Fi 和远程互联网访问。
- 复杂的自学习或在线训练。

首版的核心成功标准是：三路图像稳定、胶条可测、缺陷可判、结果可追溯、设备可连续运行。产品化功能围绕这条主链路逐步增加。
